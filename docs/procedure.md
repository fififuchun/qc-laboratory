# 環境を作る

## コマンド

以下を順に実行する。

```bash
git init
uv init --bare --python 3.12
uv add qiskit qiskit-aer matplotlib pylatexenc
```

| ツール                     | 役割                        |
| -------------------------- | --------------------------- |

| `matplotlib`、`pylatexenc` | 回路図やグラフの描画用      |

        └───┘┌─┴─┐ ░ └╥┘┌─┐

| 表示 | 意味            | 回数  |
| ---- | --------------- | ----- |
| `11` | 2枚とも `1`     | 518回 |
| `00` | 2枚とも `0`     | 482回 |
| なし | 2枚が食い違った | 0回   |

## 何が起きている？

> 2枚のコインを「必ず同じ面が出る」ように結びつけて投げる実験を、1000回繰り返している。

量子ビットは「回っているコイン」にたとえられる。回っている間は `0` とも `1` とも決まっておらず、この状態を**重ね合わせ**と呼ぶ。

### コードの流れ

1. **コインを2枚用意する**：`QuantumCircuit(2)`

   `q_0` と `q_1` がどちらも `0` で始まる。

2. **1枚目を回す**：`qc.h(0)`

   `q_0` が重ね合わせになる。

3. **2枚を結びつける**：`qc.cx(0, 1)`

   `q_0` が `1` なら `q_1` を反転する。そのため、「2枚とも `0`」と「2枚とも `1`」の可能性が同時に存在する。この状態を**もつれ**と呼ぶ。

4. **コインを止めて見る**：`qc.measure_all()`

   ここで結果が決まる。2枚はセットなので必ず揃う。

5. **1000回繰り返す**：`shots=1000`

   測定すると状態は終わるので、毎回最初からやり直す。

### 結果の見方

- **回数のばらつき**：1回ごとの結果はランダムなので、ちょうど500回ずつにはならない。518回と482回は普通の範囲。
- **シミュレータ**：`AerSimulator` はMacの中で動きを再現するソフトで、本物の量子コンピュータは使っていない。
- **`01` と `10` が出ない理由**：誤りが起きない設定だから。実機ではノイズのため少し出る。

### 注意

- **コインはあくまでたとえ**：本物のコインと違い、量子ビットは測定するまで結果が決まっていないと考えられている。
- **この結果だけでは、もつれの証明にはならない**：「同じ結果を2枚の紙に書く」ような古典的な仕組みでも、同じ結果を再現できるため。

## どう有用？

> ベル状態は単体で計算を速くするものではなく、量子通信や量子計算を組み立てるための基本部品として役立つ。

- **盗み見に気づける暗号通信**：離れた2人がペアを1つずつ持って測定すると、同じ乱数が手に入り、暗号の鍵に使える。盗み見があると結果の揃い方が乱れるので気づける。
- **量子テレポーテーション**：ベル状態のペアと通常の通信を組み合わせて、量子ビットの状態を離れた場所へ移す。量子ビットの状態はコピーできないため、元の状態は消える。
- **量子計算の材料**：もつれは量子コンピュータの強みに欠かせない要素のひとつ。グローバー探索や、誤りを検出・訂正する仕組みでも使われる。
- **実機の性能チェック**：実機でベル状態を作り、`01` や `10` がどれだけ出るかを見ると、そのマシンの誤りの多さがわかる。

もつれを使っても、光より速くメッセージは送れない。自分の測定結果はランダムで狙った値を選べず、相手と結果を比べるには普通の通信が必要になるため。

## 実機ではどう実行している？

> シミュレータは数値を計算し、実機は量子ビットへの物理的な操作で同じ回路を実行する。

ここではIBM機で使われてきた超伝導量子ビットを例にする。方式や数値は機種によって異なる。

### 基本の仕組み

- **量子ビット**：絶対零度近くまで冷やした、極小の超伝導回路。
- **`h` のようなゲート**：狙った量子ビットに、決まった長さのマイクロ波パルスを当てる。
- **`cx` のようなゲート**：隣り合う2つの量子ビットの間に相互作用を起こして、2つの状態を一緒に変化させる。
- **測定**：量子ビットの状態を読み出し回路で検出する。ここで情報が外に出る。

### `cx` で行っていること

1. **隣の量子ビットとつなげておく**

   量子ビットは電気回路で、隣とはコンデンサなどの部品を介してつながっている。ばねでつないだ2つの振り子のようなもの。

2. **相手の振動数に合わせたパルスを当てる**

   `ecr` で使われる方式では、`q_0` に `q_1` の固有振動数のマイクロ波を当てる。影響はつながりを通して `q_1` に伝わる。

3. **`q_0` の状態によって `q_1` の反応を変える**

   `q_0` が `0` のときと `1` のときで、`q_1` の回り方が反対になる。

4. **パルスの長さと強さを調整する**

   反応の差がちょうどよくなる長さで止め、ほかの補正を組み合わせて `cx` と同じ動きにする。

`cz` で使う方式では、スイッチの役割をする部品（カプラ）を2つの間に置き、ゲートの間だけつなげる。

### なぜ「読む」ことにならないのか

反応は誰かが `q_0` を確認して起こすものではなく、回路の物理法則で自動的に決まる。`q_0` が重ね合わせなら、「`0` の場合の反応」と「`1` の場合の反応」が同時に進む。結果が外に記録されないので、重ね合わせは壊れない。

### 実機ならではの制約

- **`cx` がそのまま実行されるとは限らない**：機種ごとに使える基本操作があり、`transpile` が `ecr` や `cz` などを組み合わせた操作に置き換える。
- **隣同士にしかかけられない**：離れた量子ビットには、`swap` で状態を隣まで運んでからかけるので、`transpile` が処理を追加する。
- **誤りが起きやすい**：`cx` のような2量子ビット操作は、1量子ビット操作よりも誤りが大幅に多い傾向がある。実機で `01` や `10` が少し出るのは、このような操作や読み出しの誤りが原因。
